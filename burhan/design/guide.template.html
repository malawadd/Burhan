01 / THE IDENTITY

Field-first.
Evidence-led. Unmistakable.

Burhan’s design combines dark neobrutalist structure with restrained Material controls. The workspace feels like an organised field notebook. The camera gives the scene priority. Yellow tells you where to act.

PRINCIPLE / 01

Clarity over noise.

One selected check. One short next instruction. One dominant capture action. Keep explanations in Details instead of filling the preview.

PRINCIPLE / 02

Trust through evidence.

Show the observation, its photograph and its review state. The design separates a model suggestion from a finding confirmed by a person.

PRINCIPLE / 03

Built for the field.

Strong contrast, generous targets and direct language. The app’s English and Arabic experiences carry the same hierarchy and respect each reading direction.

The character is construction precision with human judgement.

Give the mark room.

For content, leave at least one bar-width around the three-bar mark and one cap-height around a complete lockup. This is a practical production rule for this kit.

Keep it structural.

Preserve the three bars, their stepped proportions and slant. Use a single colour on busy imagery. Keep the wordmark level; the bars supply the angle.

Know the product variants.

The workspace uses the bar mark and wordmark. The native camera uses a compact BURHAN wordmark. The Arabic name is برهان.

02 / COLOUR SYSTEM

Charcoal does the work.
Yellow gives the signal.

These values come from the shipped workspace styles. Click any swatch to copy its hex value. Use the neutral surfaces as the canvas; keep yellow concentrated on actions, attention and identity.

03 / TYPOGRAPHY

Strong headings.
Calm instructions.

Use a direct sans serif, tight English headings and open, readable body text. Small uppercase labels give the workspace its technical rhythm. Arabic keeps natural letter connections and needs more vertical space.

What the app actually uses

The web workspace uses Segoe UI / Arial with Noto Sans Arabic fallback. Native Material controls use the device’s system sans serif. Reports bundle Noto Sans and Noto Sans Arabic. This portable guide embeds both Noto families, with weights 100–900, so the file also opens offline.

For graphics and editing

Use the bundled Noto families when a matching system font is unavailable. Keep Latin headlines bold and compact; set Arabic in its own direction with comfortable leading. Avoid faux Arabic letter-spacing, display scripts and ultralight captions.

Shape & depth

Workspace corners: about 3 px. Native buttons: 5 dp. Browser sheets: 18 px. Primary web actions use a 3 px solid offset shadow, not a soft glow.

Icons & labels

The workspace uses Lucide outline icons. Pair icons with short action labels. Keep a consistent stroke weight and avoid mixing emoji with the icon system; the AI star is a deliberate exception.

Touch & focus

Maintain at least 48 dp camera touch targets. Show a clear focus outline for keyboards. Enlarge text without hiding core capture controls. Colour supports meaning; the label supplies it.

05 / UX & MOTION

The person stays
in control.

When you demonstrate Burhan, preserve the sequence. A suggestion is not an active check. A detection is not a confirmed finding. A captured photo is not a completed inspection.

01 / ORIENT
EXPLORING

See the area.

No check is selected. The automatic defect detector is inactive. Keep the camera prominent and the instruction short.

02 / CHOOSE
AI PROPOSES

Tap to inspect.

A small hint proposes a relevant check. A tap selects it. Swiping it away leaves the current check unchanged. The reason lives in Details.

03 / RECORD
INSPECTING

Capture evidence.

The check title, indicator, instruction and detector agree. Capture confirms only after storage. Stop, deselect, Complete or Skip returns to Explore.

04 / REVIEW
HUMAN REVIEW

Make the record.

Review original and annotated images. Confirm findings, record actions and generate a saved report. A report preserves the evidence of that version.

Disclosure stays honest.

Local detection and evidence storage work offline. Smart guidance uses the paired online backend. Show “cloud analysis” and “assistant unavailable” states when relevant.

Optional tools stay optional.

Zoom gestures, volume capture, overlays and other tools belong in Camera & Capture. Markup and photo sharing appear in Review when enabled.

Never edit a verdict into existence.

A model score is not severity or accuracy. Preserve the difference between Needs review and Confirmed. Empty detection is not an automatic pass.

✦ Try: Wall joints ›

Native hint: 160 ms fade + 6 dp slide. Browser: 180 ms. No automatic reading timeout. Respect reduced-motion settings; keep editor transitions equally restrained.

A visual system
you can make content with.

Use actual inspection footage, sharp crops, large plain-language headings and quiet technical details. Let the evidence lead. The following canvas layouts and timing are suggested content treatments, not shipped app screens.

Vector composition / suggested campaign direction. No simulated inspection result or accuracy claim.

COMPOSITION LAB / VECTOR EXPORT

One system.
Three working canvases.

Choose a ratio, then download an editable SVG. The layouts carry the same yellow, charcoal, stepped mark and direct tone as the app.

WORKING MARGIN / 8%Make room for the message.

Canvas sizes: 1080 × 1920, 1080 × 1080 and 1920 × 1080. The 8% margin is this kit’s working grid, not a platform-safe-area guarantee. Check the destination crop and interface before export.

Framing

Use close, useful views of materials and real actions. Keep the phone screen legible; hold a clear state rather than zooming constantly.

Graphic devices

Thin grids, corner brackets, section numbers and short ruled lines. The three-bar mark carries enough character; it does not need extra construction clip art.

00—03 / OPEN

Start with the name.

BURHAN / برهان. “Built on evidence.” A strong yellow-on-charcoal title.

03—08 / ORIENT

Show the real area.

Open the camera in Explore. Hold the view long enough to understand the element.

08—14 / CHOOSE

Tap the suggestion.

Make the human selection visible. Show the selected title before any detector result.

14—20 / CAPTURE

Save the evidence.

One deliberate capture. Wait for successful storage and the evidence count.

20—26 / REVIEW

Show the judgement.

Original, annotated evidence and a human review state. Use real product behaviour.

26—30 / CLOSE

End with the record.

Show the report archive, then a clean name and call to action. Use an actual saved report.

Motion & sound

Short cuts, restrained slides and useful pauses. A quiet shutter or confirmation sound may support the action; constant scanning beeps imply behaviour the app does not promise.

Captions

Use one sentence at a time. Keep captions away from the check title, camera controls and evidence labels. Enlarge a cropped UI detail instead of making it unreadably small.

Footage priority

Prefer real on-site actions and actual app captures. The HTML specimen illustrates a layout; it is not footage of a working detector. Keep that distinction in the finished edit.

08 / VOICE & COPY

Confident about the tool.
Precise about the claim.

Speak like a capable field colleague: direct, specific and useful. Describe what the inspector can do. Keep English and Arabic natural rather than forcing literal slogans or technology jargon.

What is an existing product detail, and what is a content suggestion?

Colour tokens, interface labels, mark proportions, component styles and the delivered workflow are taken from the app source and evaluation captures. The portrait/square/wide layouts, 8% production margins, suggested Arabic content line and 30-second edit are creator directions in this guide. The interactive phone is a reconstruction with an illustrated scene, not a recording or a vision model. No app code or APK has been changed to create this guide.

Which screenshot should I use?

Use browser references for image review and guidance demonstrations; their labels identify an imported evaluation image. Use native fixtures to understand Android hierarchy and Arabic layout. Their black camera area is deliberate. For a live-camera promotional video, capture actual footage on a phone. The supplied files are reference assets, not a claim of physical-device performance.

How do the SVGs and fonts work in an editing tool?

The bar mark is vector geometry reconstructed from the shipped CSS. SVG wordmarks and campaign layouts keep editable text. Select or install the bundled Noto Sans / Noto Sans Arabic fonts in your editor, and confirm line breaks after importing. The font files are variable fonts with weight ranges 100–900. Their original OFL license files are included in the companion asset pack. System fonts such as Segoe UI and the Android system font are not bundled.

Source and version notes

Reference product: Burhan 1.3.0, version code 5. Source references: src/styles.css, src/engine/Scanner.css, src/i18n.ts, InspectionCameraUi.java and v1.2 evaluation screenshots. The light reading surface of this guide uses the product’s light-theme neutral family. Native and web control shapes intentionally differ. This is a creative handoff, not a new implementation specification or a UI compliance certification.
