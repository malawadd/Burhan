# Local inspection workspace UI

The dashboard is served from the runtime's own origin. It uses plain HTML, CSS and browser JavaScript, with system fonts and no CDN, external library, analytics, account or remote service. Opening it only reads runtime state; it does not start a camera or stream automatically. An already-running local runtime is displayed when the browser reconnects.

Choose Factory, Freight or Roads in the sidebar, select a camera, video, image, image folder, PDF or synthetic demo, then explicitly press **Start inspection**. The Public-data example selector fills installed sample paths and explicit model settings without starting the source. Local model settings passes a JSON options object to the selected adapter. A different profile/source selection takes effect on the next start; the current preview continues to show its actual running profile. Event image saving and manual factory unit triggers are visible and default off. Saving refers to event images, not continuous video recording. The source badge distinguishes synthetic evidence, live local camera, video and local image/document input.

Profile controls expose implemented backend actions: factory reference approval in reference mode and optional unit triggering; freight page capture; and profile reset. A capture request never bypasses freight quality checks. The current-inspection card displays backend findings, method-specific scores and next actions without converting scores into percentages or confidence. Freight shows configured required page types, extracted OCR text/fields and unverified evidence. Road model output requires review. Persistent review decisions require a future backend contract.

State refreshes at 2 Hz, annotated JPEG preview at approximately 6 Hz and local event history every two seconds. Requests are guarded against overlapping state/preview work. Browser tab visibility pauses preview fetching. Preview URLs are revoked to avoid accumulating image buffers. API and event payload text is inserted with `textContent`; arbitrary server-provided strings are not interpreted as HTML. Errors from explicit actions are surfaced to the user. Runtime connection loss marks the preview stale; stopping retains the last preview with a stopped label. A changed session clears the prior preview.

Advanced settings independently limit server preview encoding to 0–15 FPS (six by default). Zero disables preview and shows an explicit placeholder; inspection continues. The browser fetch limit remains approximately six FPS. Media encoding errors and rejected evidence images are surfaced in the health banner. Preview sampling never skips model inspections, and a displayed image can lag the latest decision.

Metrics come from `/api/state`: host-receipt-to-decision p95/p50 latency, processing/capture FPS, captured/processed counts, dropped/late frames, missed units, coverage gaps, evidence writer queue/losses and inspection errors. Latency begins after a frame is read on the host and excludes camera exposure, camera/backend buffering and browser rendering; camera delay is explicitly unmeasured. Factory always uses bounded FIFO, including continuous mode, with overflow reported. Freight and roads use a latest-frame queue that drops stale frames. The dashboard labels these queue policies separately. Missing values are shown as dashes. Delays, drops and lost events are not hidden or replaced by simulated measurements. History includes the full JSON payload in expandable records. Export downloads the actual `/api/export` response.

The camera request and generated demo default to 960 × 540; real camera negotiation may differ. Still-image and PDF geometry is preserved subject to documented size limits. Camera selection in the dashboard is device 0; other camera indices are accepted by the API. Local paths are resolved on the edge machine rather than uploaded from the browser. Factory reference approval is an explicit operator assertion. Surface-model mode is explicit and hides the reference-approval control. The dashboard runs on the same trusted machine as the runtime; remote authentication and TLS are outside this local prototype.

## Verification

Static checks should verify every JavaScript DOM ID exists, JavaScript parses, no external resources are referenced, expected API endpoints match the server, and default saving/trigger checkboxes remain unchecked. Once the server is running, exercise each synthetic profile, stop/restart, reference approval, freight capture/reset, export, invalid file path, and connection loss. Confirm browser-level errors are absent and metrics are real. Narrow-layout checks should cover the stacked workspace, visible controls and readable tables.
