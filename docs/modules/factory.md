# Factory module

**Accuracy update:** the latest [mask-aware study](../factory-accuracy-improvement.md) did not achieve higher localized-defect recall: the reused comparison remains 8/11 (72.7%). Review thresholds are retained as experiments, not shipped as an accuracy upgrade. Fused neural inference improves measured precision/speed but still misses the same defects. Whole-frame classification flags must not be counted as successful localization when their boxes are elsewhere.

**Real-input update:** a second, explicitly selected local model now detects surface-defect candidates on real KolektorSDD images. Use `defect_model_path` with the locally trained Random Forest and its metadata; see [factory model, dataset, reproduction and evaluation](../models/factory-surface.md). The original approved-reference mode remains the default for real camera/product calibration. The surface model is restricted to its own acquisition family and is not automatically applied to an arbitrary camera.

This CPU baseline detects selected visible differences from an **explicitly approved reference** for one fixed-view product family. It does not diagnose internal machinery faults, test electrical function, classify arbitrary defects, or replace industrial AOI. `FactoryProfile()` starts uncalibrated. Call `calibrate(frame)` / `set_reference(frame)`, pass a BGR `reference` array, or configure `reference_path`. A failed calibration retains the previous reference and returns an error. Operator approval is a declaration: the software cannot prove a reference is good.

`FactoryProfile({"demo": true})` explicitly selects a self-authored synthetic board reference. `demo_frame(index)` renders 60 clean frames, 60 with an omitted component body, 60 with a foreign scratch, and 60 with a displaced component, repeating. Detection does not read the index, sequence or scenario label: it registers and compares actual pixels. Original generated images carry no scenario label. The returned annotation and state mark synthetic demo mode. Camera use must use an operator-approved camera reference; a synthetic reference is not camera calibration.

## Local processing

The pipeline below describes approved-reference mode. Model mode uses native image geometry -> quality/view checks -> aspect-preserving bounded-grid OpenCV grayscale texture features -> local Random Forest scores -> connected-component threshold -> the same temporal/per-unit event semantics. Model mode does not require ORB registration or a single approved reference; it uses task-specific supervised training. A bad or missing explicitly selected model fails instead of falling back silently.

Input validation -> grayscale contrast/sharpness -> ORB feature correspondences -> RANSAC partial affine registration -> registered Gaussian reference difference -> threshold and morphology -> area-filtered regions -> consecutive spatial-overlap confirmation -> local review event. Annotation boxes map back to the original input coordinates. Registration matrices and threshold/area measurements appear in metrics; no probability score is claimed. Large scene changes, unsupported resolution, poor image quality and failed registration produce `needs_input` or `inconclusive`, never `clear`.

Continuous observation defaults to three overlapping positive frames before `fault` and one event until three clean frames rearm it. Explicit `FrameContext.unit_id` selects per-unit observation with one-frame confirmation by default; multiple images of the same unit do not emit duplicate events. Configure `trigger_confirmation_frames` if a triggered item actually supplies multiple views. `reset()` clears event history while preserving the approved reference. Quality failures break temporal confirmation. There is no stop/reject actuator.

Untriggered video has **no every-item coverage guarantee**. The host runtime must enforce capture/trigger association, bounded queues, unit deadlines and explicit late/missed inspections. This module makes no real-time deadline guarantee. Runtime timing must include capture, queue, inference, evidence and any actuator path. AWS is not involved in this per-frame decision.

## Configuration

- `demo`: default false. Explicit synthetic demo reference only.
- `defect_model_path`: optional explicit locally trained factory surface artifact. Selects model mode; requires its `.json` metadata and matching checksum. Never supply an untrusted joblib artifact.
- `defect_backend`: defaults to `auto`, selecting the explicitly built/checksum-matched `native_cascade` or a visibly reported `threshold_cascade` fallback. Both skip remaining tree votes only when their maximum possible sum cannot reach the existing pixel threshold. Candidate decisions and scores stay exact; rejected score-map pixels are labelled lower bounds. `sklearn` evaluates every tree/pixel for reproducible baseline comparisons or exact full score maps. Model hash, features, thresholds and resolution are identical in all backends. See [factory optimization](../factory-performance.md).
- `model_min_sharpness`: model-mode Laplacian variance floor, default 8; acquisition-specific.
- `reference` / `reference_path`: approved uint8 BGR reference with stable features.
- `min_sharpness`: Laplacian variance floor, default 25; camera-specific, not universal.
- `difference_threshold`: 0–255 grayscale difference threshold, default 28.
- `minimum_area`: contour area floor in reference pixels, default 65.
- `maximum_changed_fraction`: default .22; larger changes become inconclusive.
- `ignore_regions`: list of `(x, y, width, height)` in reference coordinates.
- `confirmation_frames`, `trigger_confirmation_frames`, `clear_confirmation_frames`: default 3, 1, 3.

## Experimental review and neural artifact contracts

Locally generated review artifacts set `manual_review_only=true` in their checksum-associated metadata. A confirmed candidate then returns `review`; an observed frame without a candidate returns `no_candidate`, never `fault` or `clear`. Both require human judgment. Findings are labelled `surface_review_candidate`; domain state records `automatic_acceptance=false`, `automatic_rejection=false`, `physical_unit_disposition=not_decided` and `completed_unit_semantics=inspection_observation_only`. A triggered unit may finish an observation without receiving any machine disposition. These experiments are not the default factory accuracy policy.

`describe()` exposes `model_metadata_sha256`, `decision_threshold`, `minimum_component_area` and optional `region_decision_threshold`, alongside the weight hash. Persist these fields with evidence: two operating policies can have identical weights and different thresholds. The metadata hash identifies exact loaded policy bytes; effective settings identify the current decision rule. The model path alone is insufficient provenance.

The experimental fused MobileNet artifact is local ONNX rather than joblib, with a local `.onnx.json` checksum/provenance file. It requires `defect_backend=auto` and explicitly selects OpenVINO on the installed Intel GPU, reporting `openvino_gpu_neural`; an unavailable GPU fails instead of silently changing execution device. RGB normalization, frozen early convolution features, upsampling and the learned pointwise head run in the graph. GPU logits are converted to uncalibrated sigmoid scores on the CPU. There is no runtime Torch dependency, upload or model download. Despite improved measured precision and speed, this artifact does not improve the defective-view recall and is retained as research evidence.

## Validation and limitations

Reference-mode tests use self-authored synthetic pixels: explicit calibration; clean board; omission/scratch/displacement; an independently drawn foreign patch; blank/blurred inputs; camera translation; original-coordinate boxes; unrelated textured scenes; resolution change; per-unit events; and an invalid reference path. Model tests additionally exercise a trained/persisted forest, real feature extraction, coordinates, temporal and unit semantics, abstentions, missing/tampered artifact failures, and feature-version checks. These are functional regression tests, **not independent accuracy benchmarks or factory field validation**. A separate item-held-out experiment on the downloaded public industrial surface dataset is documented in the [model report](../models/factory-surface.md). No public PCB dataset or pretrained PCB model was evaluated. Clean synthetic frames and a controlled three-fault vocabulary do not establish performance on real PCB revisions.

Validation on 20 October 2026: `python -m pytest tests/test_factory.py -q` passed all 10 tests. A serial CPU run over 120 measured 960×540 synthetic frames after five warm-up frames measured **40.76 ms p50, 79.38 ms p95, 83.19 ms p99, 84.27 ms maximum** for `process` only (Python 3.13.5, OpenCV 5.0.0, Intel64 Family 6 Model 142 Stepping 10). Capture, rendering, storage, actuator and network time are excluded. This observation does **not** establish 30 FPS processing, industrial deadlines, thermal stability or performance on an edge appliance. Shared-machine load and ORB scene complexity affect timing. The runtime must select and validate a sustainable input/trigger rate rather than silently drop units.

Inspect `laplacian_variance`, `grayscale_std`, `registration_matches`, `registration_inlier_ratio`, `changed_pixels`, `changed_fraction`, `candidate_regions` and `confirmation_count`. Runtime should measure processing p50/p95/p99, throughput and late/missed units. Measure recall across all defective inputs, accepted-input recall, abstained defective/normal counts and coverage separately on an untouched representative test set before claiming accuracy.

Likely failures include reflections, large lighting differences, changing components, camera perspective, weak texture, legitimate revision changes, tiny/subpixel faults, occlusion and low-contrast defects. Some global registration can absorb whole-object displacement; use fixtures/independent pose checks if position itself is a required tolerance. Gray differences can miss equal-luminance color errors. Finite confirmation counts represent observed frames, not time or independent samples. Continuous event latching suppresses duplicate alarms and may group adjacent faults until clean observations rearm it; this is not item tracking. Explicit triggers and validated deadlines are required for production-line integration.
